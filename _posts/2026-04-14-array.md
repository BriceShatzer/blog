# Squad 8 Onboarding Overview

## The Monorepo — What It Is

This is Array's single repository for all Go, JavaScript, and Python services. It's large and multi-team — the README even warns that the general setup docs are outdated, and **squad-specific onboarding is the right path**.

---

## Squad 8's Domain

Squad 8 builds the **Subscription Manager** product — it lets end users see their recurring payments/subscriptions, cancel or negotiate them (via Billshark), and manage linked accounts. You own three backend Go services and the frontend widget:

| Service | Location | What it does |
|---|---|---|
| `external-subscription` | `golang/pkg/services/external-subscription/` | Core subscription backend (port 5230). Stores subscriptions, handles cancel/negotiate workflows via Temporal, exposes `/api/subscription/v4/*` |
| `external-transaction` | `golang/pkg/services/external-transaction/` | Discovers recurring payments from bank transactions, publishes them to Pub/Sub for subscription-manager to ingest |
| `external-sse-proxy` | `golang/pkg/services/external-sse-proxy/` | SSE proxy streaming real-time events (Pub/Sub → browser) |
| `array-subscription-manager` | `js/website-webcom-svelte/components/default/array-subscription-manager/` | Svelte frontend widget (`<array-subscription-manager>`) |
| `array-subscription-manager-mini` | `js/website-webcom-svelte/components/default/array-subscription-manager-mini/` | Smaller variant of the widget |

The rough data flow: **external-transaction** finds recurring payments → publishes to Pub/Sub (`subscription-sync` topic) → **external-subscription** ingests them into its DB → **frontend widget** renders them via REST + SSE.

## Getting It Running Locally

The onboarding checklist in `SQ08-HandyTools/onboarding-fast-track.md` is the canonical source. Here's the prioritized order:

### Step 0 — Access you need first
- GitLab + monorepo clone
- **Doppler**: `brew install dopplerhq/cli/doppler` → `doppler login` → `doppler setup --project monorepo --config dev`
- Docker Desktop running
- Temporal UI access (ask your EM for the namespace URL)
- A dev `appKey` + `userToken` (or use sandbox self-serve flow)

### Step 1 — Docker network baseline (one-time)
```bash
docker network inspect array >/dev/null 2>&1 || docker network create array
cd golang && make init_docker
```

### Step 2 — Frontend with mock API (fastest, no backend needed)
This is the best starting point for UI work. The mock API at `https://mock.array.io` returns fake data — no local backend required.

```bash
# From monorepo root:
cd js && nvm install && nvm use        # uses js/.nvmrc
npm install -g pnpm@9
cd js && pnpm install && pnpm run build:lib

# Add to /etc/hosts:
# localhost:5141 array-local-testing.localhost:5141

# Build assets, then start dev server:
pnpm run --filter website-webcom-svelte build-assets-local
pnpm run --filter website-webcom-svelte dev    # runs at http://localhost:5141
```

Then open:
```
http://localhost:5141/cms/v3/60CDFC3B-188E-41B8-A475-D495CC4645F2/array-subscription-manager?mode=premium&apiUrl=https%3A%2F%2Fmock.array.io%2Fapi&appKey=60CDFC3B-188E-41B8-A475-D495CC4645F2&locale=en-US&userToken=A7047EED-7850-456A-BE1C-F3EAE28C9BFF
```

> If the dev server errors about a missing component, check `js/website-webcom-svelte/src/vite/plugins/get-plugins.ts` — the `releaseTag != 'dev-hmr'` guard may be missing from the if-statements.

### Step 3 — Backend: external-subscription service
```bash
# From monorepo root:
doppler run -- docker compose -f docker-compose/buildcredit.yml --profile subscription up -d

# Verify it's healthy:
curl -s http://localhost:5230/_health
```

If you hit secrets/migration issues, see `SQ08-HandyTools/environment-setup/LOCAL_DOCKER_SETUP.md`.

### Step 4 — Backend: external-transaction (tests)
```bash
# Spin up test DB:
docker compose -f ./docker-compose/buildcredit.yml up testgres -d --build
# Postgres at localhost:5433, user/password: array

# Run tests:
cd golang && go test -v -timeout 120s ./pkg/services/external-transaction/...
```
